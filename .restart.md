- retrieval search supports document scope and created-at date bounds.
- `node-context` returns a node with document metadata, parent, and children.
- `compile-context` emits a context document with role-tagged focus, ancestor, sibling, and descendant records.
- `render-context` turns compiled context into Markdown with configurable character budget and include/skip metadata.
- `build-prompt` wraps rendered context with system instruction, user query, budget metadata, and an estimated token envelope.
- `ask` retrieves/builds a prompt, runs the configured answer adapter, and stores an exchange.
- `chat` provides a simple interactive CLI loop.
- `history` lists saved exchanges.
- `sessions` lists session metadata and legacy exchange session IDs.
- `create-session` creates a named session record.
- `ask` and `chat` use `ollama_cli` by default and can pass `--adapter mock` for deterministic diagnostics.
- `ask` and `chat` can use `--model <name>` to override the Ollama model per request.
- `ask` and `chat` can use `--retrieval-mode agentic` for the first planner-driven retrieval loop.
- `ollama_cli` sends prompt text over stdin, has a 45-second default timeout, and web failures are shown in the answer run log instead of leaving the UI on `Thinking...`.
- `ask` no longer fails when no Mongo node is found; it sends the submitted prompt to the selected answer adapter with empty retrieved context.
- FastAPI web UI can search nodes, focus a node, ask questions, and show recent history.
- FastAPI web UI exposes `/api/runtime` and lets the ask panel choose `mock` or `ollama_cli` plus an Ollama model.
- FastAPI web UI exposes `/api/sessions` and lets the ask panel create/select sessions.
- FastAPI web UI lets the ask panel choose direct or agentic retrieval mode.
- FastAPI web answer panel includes a structured console trace with ordered step input/output data for prompt intake, retrieval/context compilation, and answer adapter execution.
- Agentic retrieval mode performs planner adapter call, allowed tool execution, then answer adapter call. Current allowed tools are `search_nodes`, `compile_context`, and `list_documents`; brittle planner search text is normalized and falls back to meaningful query terms.
- Web operator panel can show queue status, process `data/ingest/`, and list recent jobs.

Current implementation decisions:

- build against real MongoDB from Stage 1;
- target current 8GB RAM plus GTX 3060 hardware;
- build CLI/dev commands before the web UI;
- store implicit endorsement as MongoDB tree/node metadata, not as a filename convention;
- reject duplicate files by SHA-256 checksum and notify the requestor;
- copy accepted files into the archive;
- store label definitions in MongoDB with descriptions;
- keep `llama-cpp-python` optional rather than making it a Stage 1 dependency.
